Theming

How light, dark and high-contrast resolve from one set of semantic tokens.

WCAG 2.2 AAStatus: stable
  • Overview
  • Token tiers
  • Same component, two themes
  • Adding a theme
  • Do and don't
  • Consuming tokens.json

Overview

Light is the default. Dark applies with [data-theme="dark"], or automatically when the OS prefers dark and the page has not forced [data-theme="light"]. The root also sets color-scheme so native controls and scrollbars follow. High-contrast tweaks apply under prefers-contrast: more and forced-colors.

Token tiers

TierPrefixRule
Primitive--palette-*, --font-*Raw values. Never used by components.
Semantic--color-*, --text-*, --space-*…Meaning-based aliases. Themes override these.
Component--btn-*, --alert-*Declared in components.css, always alias a semantic token.

Adding a theme

  1. Duplicate the dark block in tokens.css under a new [data-theme] name.
  2. Override semantic tokens only; leave primitives alone.
  3. Run check_contrast.py; every pair must pass.
  4. Regenerate tokens.json with tokens_to_json.py.

Consuming tokens.json

tokens/tokens.json is a DTCG export generated from tokens.css with scripts/tokens_to_json.py. In the Angular workspace the TypeScript theme remains the source for the product; this file is the design-system reference for tools such as Style Dictionary.
