Accessibility

The WCAG 2.2 AA commitments the system makes and how to verify them.

WCAG 2.2 AAStatus: stable
  • Overview
  • Commitments
  • Focus ring
  • Testing procedure

  • Tokens

Overview

The system targets WCAG 2.2 AA. Accessibility is built into the tokens and components so pages inherit it: contrast is checked per token pair, the focus ring is one shared style, targets have minimum sizes and reduced motion is a token switch.

Focus ring

One ring for every control: 2px --color-focus-ring with a 2px offset, at least 3:1 against what it sits on.

<button class="btn" type="button" data-state="focus">Focused</button><input class="input" aria-label="Focused input" data-state="focus" value="Focused" style="max-width: 12rem;">

Testing procedure

  1. Run check_contrast.py and check_design_system.py.
  2. Tab through the page: order matches reading order, ring always visible, no traps.
  3. Operate each widget with its documented keys.
  4. Zoom to 200% and resize to 320px.
  5. Run a screen reader pass (NVDA + Firefox, VoiceOver + Safari) on dialogs, forms and toasts.
  6. Toggle prefers-reduced-motion and forced-colors.

Component contract

Each component page answers seven questions under Accessibility: the pattern, the keyboard map, focus behaviour, labelling, contrast pairs, motion and touch size.
