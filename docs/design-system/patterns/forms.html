Forms

Layout, validation timing, summaries and submit states for every form.

WCAG 2.2 AAStatus: stable

Overview

Forms collect the minimum needed. They are single column, validate when the reader leaves a field, and summarise errors after a failed submit.

When to use which

SituationUse
Few fields, one taskSingle-column form on a page
Edit one thing from a listDialog form
Five or more stepsWizard with a stepper
Preference toggleSwitch, applied immediately

States

  • Validate on blur, then re-validate on input once an error is shown.
  • Submitting: the pressed button shows aria-busy; fields stay editable only if resubmitting is safe.
  • Failed: focus moves to the summary; each entry links to its field.

Responsive behaviour

Fields stack in one column at every width. The actions bar keeps back on the left and the primary action on the right; on phones the primary action is full width.

Accessibility

Every control has a label; errors use aria-invalid and aria-describedby; the summary receives focus after a failed submit; use autocomplete tokens for personal data.

Content

Labels are nouns; errors say how to fix it; the submit button says what happens next.
