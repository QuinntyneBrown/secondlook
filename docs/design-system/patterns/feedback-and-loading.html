Feedback and loading

Which feedback for which action, and which loading indicator for which wait.

WCAG 2.2 AAStatus: stable
  • Overview
  • When
  • Structure
  • States
  • Responsive
  • Accessibility

Overview

Match the weight of the feedback to the weight of the event. Inline for field-level, toast for a completed action, banner for page state, dialog for decisions. Show a skeleton for page content, a spinner for short actions and a progress bar for measurable work.

When to use which

EventFeedback
Field invalidInline error
Action succeededToast (8s, pausable)
Window expiringPersistent banner
Irreversible choiceDialog
Page loadingSkeleton
Button action in flightButton loading
Upload with totalProgress bar

Structure

Window ends soon
Add a car

States

  • Optimistic: apply immediately, offer Undo in a toast.
  • Pending: keep the layout stable; never replace content with a lone spinner longer than a second.
  • Failed: say what failed and offer Retry.

Responsive behaviour

Toasts anchor to the bottom on phones and a corner on larger screens; banners span the width under the topbar.

Accessibility

Toasts live in role=status (polite) or role=alert (errors); they never take focus and never cover the focused control; busy containers set aria-busy.

Content

Past tense for success, a fix for failure.
